# air-ssh による機器操作

既存の `air-ssh` CLI を使う。独自の SSH 接続スクリプトを作らない。
対象は AireOS WLC / Mobility Express のコントローラー CLI。
AP 自身の CLI や IOS XE のコマンドを混ぜない。

## 実行環境と対象を決める

インストール済みなら `air-ssh`、aironet のリポジトリで開発環境を使うなら
リポジトリ直下から `uv run air-ssh` を実行する。まず `--help` で利用可能な引数を確認する。
以降の例の `wlc` と WLAN ID は例示であり、実際の対象に置き換える。

```console
air-ssh --help
air-ssh --list
air-ssh --device wlc "show sysinfo"
```

- インベントリの選択順は `--inventory PATH` → 環境変数 `AIRONET_INVENTORY` → `~/.aironet/devices.json`。
  `--list` は接続せず、参照先と機器名・ホスト・ユーザー名を表示する。
- 対象は依頼・会話の指定と `--list` を照合し、`--device NAME`（`-d`）で明示する。
  `AIRONET_DEVICE` の指定も使える。複数候補から先頭の機器を勝手に選ばない。
- 資格情報は CLI に解決させる。パスワードの選択順は機器の `password` →
  `password_env` が指す環境変数 → `WLC_PASS`。一覧確認のためにインベントリ全体や環境変数の値を表示しない。
  資格情報不足は必要な設定箇所を伝え、秘密値を会話やリポジトリに書かせない。

機種・実行版は既知の情報を使い、実機調査の範囲なら `show sysinfo` で確かめる。
構文や制約が不明な場合は、ローカルの変換済みマニュアルを確認する。
`air-manual` が利用可能ならその手順を使い、無ければ
`AIRONET_MANUALS`（未設定なら `~/.aironet/manuals/`）の該当冊子の索引から本文を読む。

## 状態を確認する

必要な表示コマンドを、1 コマンドにつき1つの引用符付き引数として渡す。
コマンドは空でない1行にし、改行でまとめたり、シェルの区切り記号で連結したりしない。

```console
air-ssh --device wlc "show ap summary" "show client summary"
```

状態確認の依頼から設定変更・再起動・保存へ進まない。
出力は逐次表示される。共有する抜粋に秘密値が含まれる場合は伏せる。

## 設定変更と WLAN サイクル

投入前に対象機器、実行する設定行、影響する WLAN、通信断の有無、保存の要否を具体化する。
対象と変更内容が依頼ですでに承認されていれば再確認を求めず、その範囲で進める。
未確定の対象や依頼を超える通信断・変更が必要な場合は、その点だけユーザーに確認する。
CLI は確認プロンプトへ自動で `y` を返すため、機器側の確認待ちを承認の代わりにしない。

変更前の関連設定と状態を読み、機種・版に合う構文、引数の順序、前提条件を確かめる。
WLAN を止める必要がある変更には、該当する変更の直前に `--cycle-wlan ID` を置く。

```console
air-ssh --device wlc --cycle-wlan 1 "config wlan max-associated-clients 50 1"
```

- `ID` は 1〜512。CLI は `show wlan ID` で対象の存在と元の有効・無効状態を確認する。
- 有効だった WLAN は `config wlan disable ID` を実行し、無効化を確認してから後続へ進む。
  次のサイクルの直前または処理の最後で元の状態に戻し、表示コマンドで復旧を確認する。
  コマンドとサイクルの引数順が実行順になる。元から無効だった WLAN は無効のまま保つ。
- 例外時も元の状態への復旧を試みる。切断・タイムアウトで接続が使えない場合は復旧できず、
  エラーを表示する。投入済みの設定値を元に戻す処理はない。失敗時は次のサイクルへ進まない。

## 結果を確認し、必要なら保存する

終了コードと機器の出力の両方を確認し、変更後の表示コマンドで設定値と WLAN の状態を検証する。
CLI は既知の機器側エラーを検出し、WLAN サイクルでは無効化と元の状態への復旧も確認する。
未知のエラー表現や設定値の誤りを網羅して検出するものではないため、変更後の設定値も確認する。

保存が依頼の範囲に含まれるなら、変更の検証後に同じ対象へ実行する。

```console
air-ssh --device wlc --save
```

`--save` は `save config` を送り、保存の確認プロンプトへ応答する。
`Configuration Saved!` とプロンプト復帰を確認できなければ失敗にする。
変更と同時に付けることもでき、その場合は全 WLAN の元の状態への復旧を確認した後に保存する。
設定値を人が検証してから保存したい場合は、変更と保存を別実行にする。

確認待ちの行を識別して `y` を返し、Enter 待ちには Enter、`--More--` には Space を返す。
大量出力による切断を避けるため、接続後はページ送りを有効にする。
既知の機器側エラー、状態確認の失敗、120秒の無出力で処理を停止し、終了コード 1 となる。
後続コマンドと `--save` を実行せず、タイムアウト後は同じ接続へ追加のコマンドを送らない。
タイムアウトや切断の後は適用状況と WLAN の状態を読み直し、バッチ全体を無条件に再実行しない。
復旧できない場合は追加変更・保存を止め、未確認の状態と失敗箇所を伝える。

回答には対象、行った操作、確認できた結果、保存の実施状況、未解決事項を簡潔に示す。
